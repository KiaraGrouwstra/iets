iets is a re-implementation of the Nix client in Rust. It is mostly, but not
fully, compatible with Nix. This release follows v0.1.0 with 185 commits.

## Download

One static musl binary per platform. It needs no `/nix/store`, no
nix-daemon and no shared libraries.

```sh
curl -Lo iets https://github.com/numtide/iets/releases/download/v0.2.0/iets-0.2.0-x86_64-linux
chmod +x iets
./iets version
```

`SHA256SUMS` lists the checksums. For aarch64-linux, use
`iets-0.2.0-aarch64-linux`. With Nix, `nix run github:numtide/iets/v0.2.0`
also works.

## Security

- The compiled-in CA roots (webpki-roots 1.0.10) no longer include
  `emSign ECC Root CA - G3`, and rustls-webpki 0.103.16 rejects the eight
  eMudhra intermediates that were revoked as compromised on 2026-10-18/19.
  iets uses the system store first (`NIX_SSL_CERT_FILE`, `SSL_CERT_FILE`,
  then the platform store); the compiled-in roots are only the fallback.

## New

- `iets build` takes several installables, loads each flake once, and draws
  running builds as a live region on a terminal. `--no-build` uploads the
  closure of every root. `--timings` includes the `-o` copy.
- `iets completion` prints shell completion for six shells, and the package
  installs it.
- The NixOS module puts the classic names in `nix.package`.
- `IETS_PROGRESS=false` turns off the status line on a terminal and the
  `⏵` lines on a pipe, for a log that must not depend on run time.

## Compatibility

- `nix eval --json` forces the whole value. `nix eval` takes `-L`, and the
  classic names take `--flake-registry`.
- `iets eval` with several `-A` prints each one in order, and evaluates the
  input once, as `nix-instantiate --eval` does.
- `builtins.currentSystem` is the host's system. Before, it was always
  `x86_64-linux`.
- `builtins.readFile` of a store file gives the string the references of
  its store path, so a derivation that embeds it gets the same drv path as
  under Nix.
- With parallel evaluation, `trace`, `warn` and lint warnings come out in
  the order of the sequential run, as in Nix.
- The store dir comes from `NIX_STORE_DIR`, and the daemon socket is found
  the way Nix finds it.
- `nix-shell` gives the shell every core when `cores = 0`.
- Building a file that holds a function calls it first, as Nix does.
- Flakes: a lock that `flake.nix` no longer asks for is refused, a github or
  gitlab ref named twice is refused, and `getFlake` on a `path:` reference
  takes its narHash lock in pure evaluation.
- The session gets the `nix.conf` and settings environment variables.

## Windows

Work in progress, with no release binary yet: fiber stacks grow on demand,
`path:` inputs and source paths resolve, and a Windows job runs in the
merge queue.
